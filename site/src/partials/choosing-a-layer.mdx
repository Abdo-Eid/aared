Choose how much UI and lifetime management your app owns. Every integration
uses the same renderers, so choosing a simpler entry does not reduce fidelity.

| You want to… | Use |
|---|---|
| A viewer with built-in controls | `<aared-viewer controls>` |
| A viewer in React, with app-owned UI | `usePreview()` from `@aared/viewer/react` |
| A JavaScript viewer, with app-owned UI | `preview({ source, target })` from `@aared/viewer/preview` |
| Semantic data reads or manual document lifetime/rendering | `open()` and `render()` from `@aared/viewer/pptx`, `@aared/viewer/xlsx`, or `@aared/viewer/docx` |

**Only accepting one format?** Import `preview()` from its format entry instead
of `@aared/viewer/preview`. Each format entry exports both the viewer and the manual
document operations. React also offers `usePptx()`, `useXlsx()` and `useDocx()`
for format-specific types.

**Already showing the file?** Keep using that viewer for controls and search.
Its `viewer.content` provides semantic reads and inputs for secondary renders,
such as thumbnails, without reopening the file. It does not expose document
editing or rendering models. See [multiple views](../start/#render-several-slides-from-one-document)
and [borrowed content](../api/#borrowed-content).
