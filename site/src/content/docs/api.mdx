aared previews real PowerPoint, Excel and Word files in the browser, painted
to DOM and SVG — never canvas — so text stays selectable and Arabic and other
RTL content shapes the way the browser shapes it.

This page is the reference. New here? [Start](/start/) covers installing,
picking an entry, copy-ready recipes and the usual first problems, and the
[playground](/playground/) runs every entry live.

## Choosing a layer

<ChoosingALayer />

The element, `preview()` and the hooks forward a fixed set of options; they
search the opened document (`viewer.search()`) but don't hand it out. Where
they differ from the low-level `open()` / `render()` API:

| | `<aared-viewer>` | `preview()` / hooks | `open()` / `render()` |
|---|---|---|---|
| Format auto-detection | Yes | Generic entry only | No — you choose the import |
| `appearance` beyond `theme`, `fontResolver`, `mediaResolver` | No | Yes | Yes |
| Moving within a unit: cells, headings, pages | Yes (`el.viewer.xlsx`, `el.viewer.docx`) | Yes (`viewer.xlsx`, `viewer.docx`) | Yes |
| `search()` | Yes (`el.viewer.search()`) | Yes (`viewer.search()`) | Yes |
| `read()`, `media.get()`, the collections; several units at once | No | No | Yes |

The element, `preview()` and the hooks run on one viewer, so they share its
codes, events and rules: options set where it starts, its methods change it
(see [Design principle](#design-principle)). A workbook shows its sheet tabs
in all three; the low-level `render()` leaves them off for an app that draws
its own.

**Bundle size.** The element, auto-detect preview and the hooks reach each format
through a dynamic `import()`: bundlers emit a chunk per format, and only the
detected one is fetched. Importing `aared/pptx`, `aared/xlsx` or `aared/docx`
directly puts only that format in your build. Parsing runs in one
self-contained Worker script for every format.

Use `preview()` for custom toolbars and search UI. Use the low-level API for
model access or several units sharing a document. `read()` returns the model the
renderers
paint, so reading cell values or slide text works, but there is no export or
conversion, formulas are never evaluated (cached values only), and nothing
edits.

## Packages

| Package | Purpose |
|---|---|
| `aared` | Everything below — shared core, per-format entrypoints (lazy-loaded), and `<aared-viewer>` |
| `aared-fonts` | Frozen, not published: calibrated look-alike fonts for an app that needs Office's line breaks exactly (see [`fontResolver`](#sources-and-options)) |

`aared` exposes its surface through subpath exports, so a consumer loads only
the formats it uses:

| Import | Contains |
|---|---|
| `aared/core` | Shared grammar: sources, options, collections, appearance, media, `AaredError`, and the resolved model types. Opens nothing itself. |
| `aared/pptx` | Format-local `preview()`, plus `open()`, `PptxDocument`, slide collections/handles and `render()` |
| `aared/xlsx` | Format-local `preview()`, plus `open()`, `XlsxDocument`, sheet collections/handles with range reads and `render()` |
| `aared/docx` | Format-local `preview()`, plus `open()`, `DocxDocument`, section/heading collections, `render()` and `SoftBreakPolicy` |
| `aared/preview` | `preview()`, `detect()`, `PreviewHandle` — auto-detect preview; lazily `import()`s only the detected format entrypoint at runtime |
| `aared/react` | `usePreview()`, `usePptx()`, `useXlsx()`, `useDocx()` — React hooks owning the `preview()` mount lifecycle; `react` is an optional peer |
| `aared/element` | `<aared-viewer>` — registers the custom element |
| `aared/worker` | The self-contained Worker script (`dist/core/worker.mjs`), for bundler `?url`/`?raw` imports — see [Worker override](#worker-override) |
## Web component

```html
<aared-viewer
  src="quarterly-report.pptx"
  type="pptx"
  theme="system"
  controls></aared-viewer>
```

```ts check
// Your bundled app code (see Install on the Start page).
import "aared/element";

// For content that isn't at a URL (an upload, a drop target). The import
// types the tag, so this is an `AaredViewer` with no cast:
document.querySelector("aared-viewer")!.file = myFile;
```

The element takes every format, each loaded on first use; an app that shows
one format can use that format's `open()` + `render()` instead.

### Attributes / properties

| Name | Type | Notes |
|---|---|---|
| `src` | attribute, URL | Fetched and opened automatically |
| `file` | property only | `File \| Blob \| ArrayBuffer` or a typed array, for content that isn't at a URL (drag-and-drop, upload). Of `src` and `file`, the one set last opens |
| `type` | attribute and property | `"pptx" \| "xlsx" \| "docx"` — optional assertion against auto-detection; a mismatch raises `error` (`unsupported-format`), at once when a document of another format is open |
| `index` | attribute and property, number | Zero-based unit to show. A slide and a sheet are each one unit; a DOCX document is one unit. It always names the unit on screen: a sheet tab, the controls and `viewer.goTo()` write it, and a unit that cannot be shown fires `error` and puts it back |
| `zoom` | attribute and property | `"fit-width" \| "fit-page" \| <number>` — drives the viewer's zoom, and `viewer.setZoom()` writes it back. Unset, each format opens at its default (see [Zoom](#zoom)); removing the attribute goes back to it |
| `controls` | boolean attribute | Built-in nav/zoom bar with a full-screen toggle (hidden where the Fullscreen API is unavailable), in the spirit of `<video controls>` |
| `theme` | attribute and property | `"light" \| "dark" \| "system"` (default `"light"`) — viewer chrome; document content is always source-faithful (see [Dark mode](#dark-mode)) |
| `pagination` | attribute and property | `"flow" \| "layout"` (default `"flow"`) — DOCX only: `"layout"` paints physical pages (`viewer.docx.pages`, `goToPage()`), each with the page shadow. Changing it re-opens a DOCX; other formats ignore it |
| `worker` | property only | `WorkerInit` — see [Worker override](#worker-override) |
| `viewer` | read-only property | The open document's viewer (`AaredViewerHandle`), or `null`: `format`, `info`, `index`, `zoom`, `defaultZoom`, `scale`, `goTo()`, `setZoom()`, the toolbar methods (`next()`, `previous()`, `zoomIn()`, `zoomOut()`, `resetZoom()`), `search()`, the places inside a unit (`xlsx`, `docx`) and the events. See [Methods](#methods) |

### Events

Events report **changes**. The starting state is the `load` event (or read
`index`, `zoom` and `viewer.info`): opening a file fires no `indexchange` or
`zoomchange`, and going to the unit already shown fires nothing.

| Event | `detail` |
|---|---|
| `load` | `DocumentInfo` — the document opened and its first unit painted |
| `indexchange` | `{ index: number }` — the unit changed (`viewer.goTo()`, the `index` attribute, a sheet tab, the controls) |
| `slidechange` | `{ index: number; title: string }` — PPTX, alongside `indexchange` |
| `sheetchange` | `{ index: number; title: string }` — XLSX, alongside `indexchange` |
| `progress` | `LoadProgress`, `{ loaded: number; total?: number }` — bytes read before parsing starts: each streamed chunk for a URL (`total` when the server sends `Content-Length`), one event before and one after for a `file`. Parsing reports none, so `load` or `error` follows the last one |
| `error` | `{ message: string; cause: AaredError }` — once per failure |
| `zoomchange` | `{ zoom: ZoomValue }` — the zoom changed (forwarded from the render handle) |
| `linkactivate` | Forwarded from the render handle — see each format's hyperlink notes |
| `cellactivate` | `{ sheet: { index, title }; address; row; col; model }` — XLSX, forwarded |
| `selectionchange` | `{ sheet: { index, title }; selection: { address, row, col } \| null }` — XLSX, forwarded |

Every event is typed (`AaredViewerEventMap`), so a listener reads `detail`
with no cast:

```ts check
import "aared/element";

const viewer = document.querySelector("aared-viewer")!;
viewer.addEventListener("load", (event) => console.log(event.detail.count));
viewer.addEventListener("error", (event) => console.warn(event.detail.cause.code));
```

In TSX, `<aared-viewer>` needs an entry in `JSX.IntrinsicElements`, which
you declare yourself: React is an optional peer, so aared adds none.

### Methods

```ts check
import "aared/element";

const element = document.querySelector("aared-viewer")!;
await element.open();               // (re)load whichever of src and file was set last
element.index = 3;                  // show unit 3 (zero-based); or, to wait until painted:
await element.viewer?.goTo(3);      // element.index follows
if (element.viewer?.format === "xlsx") await element.viewer.xlsx.goToCell("D14");
```

```ts
type ZoomValue = "fit-width" | "fit-page" | number;

class AaredViewer extends HTMLElement {
  readonly viewer: AaredViewerHandle | null;  // null until a document opens
  open(): Promise<void>;
}

// The preview() handle without what the element owns: `theme` stands in for
// setAppearance(), and removing the element for destroy(). Checking `format`
// narrows it the same way.
type AaredViewerHandle =
  | Omit<PptxPreview, "setAppearance" | "destroy">
  | Omit<XlsxPreview, "setAppearance" | "destroy">
  | Omit<DocxPreview, "setAppearance" | "destroy">;
```

**The attributes and `viewer` are one state.** Setting `index` or `zoom`
calls the viewer. The viewer's `indexchange` and `zoomchange` (from
`viewer.goTo()`, `viewer.setZoom()`, a sheet tab or the controls) write the
attribute back, the way `<input value>` follows typing. So `index` and
`zoom` always say what is on screen, whichever way it got there.

Failures are `AaredError`s with the codes `preview()` uses for the same
situation (it is the same viewer; see [Errors](#errors)). Each fires `error`
once with the error as `detail.cause`, and `open()` and `viewer.goTo()`
reject with that same instance. An `open()` that a newer one replaced
rejects with `aborted` and fires nothing.

### Styling

The element uses shadow DOM. Structural parts are exposed for external
styling rather than requiring a full shadow-DOM override:

```css
aared-viewer::part(stage) { background: #1a1a1a; }
aared-viewer::part(page) { outline: 1px solid #ccc; }
aared-viewer::part(controls) { font-family: system-ui; }
aared-viewer::part(button) { border-radius: 999px; }
aared-viewer::part(label) { color: #666; }
```

`toolbar` is an alias of `controls`. `page` is the box the render paints
into: the page column for DOCX, the grid for XLSX; for PPTX it stretches to
the stage and the slide inside it carries the shadow. Change the shadow with
`--aared-page-shadow` (see [Dark mode](#dark-mode)) rather than
`::part(page)`, so it lands on the right box in every format. Sheet tabs and
row and column headings are inside the shadow root, so page CSS can't reach
them; style those through a low-level `render()` into your own container.

The chrome is deliberately minimal: build custom toolbars and search UI on
`preview()`, or use `open()` + `render()` for model access and manual rendering.
`theme="system"` follows `prefers-color-scheme`, OS changes
included; the host carries `data-aared-theme`, and `data-aared-format` once a
document is open.

### Lifecycle and cleanup

The element has no `destroy()`: removing it from the document is its
teardown. It aborts pending reads, tears down the render (observers, image
object URLs) and closes the Worker session. Putting it back, or changing
`src` or `file`, opens the file again; so do changing `type` while nothing
is open and changing `pagination` on a DOCX. An open that a newer one
replaced stops before it paints, so it never covers the newer one.

Clearing the source (`file = null` with no `src`, or removing `src` with no
`file`) empties the viewer quietly, even mid-load: the page is cleared,
`viewer` goes back to `null`, and no event fires, since an empty viewer is
not a failure. Calling `open()` with nothing to open is one: it rejects with
`invalid-state` and fires `error`.

## Single-format preview

Each format entry offers the same complete viewer without including sibling
renderers. The import determines the format, skips detection and narrows the
returned handle. It owns its document: `destroy()` tears down rendering, search
state and the Worker session together. A wrong file rejects `unsupported-format`.

```ts check
import { preview } from "aared/pptx";

const viewer = await preview({ source: file, target: container });
await viewer.next();
await viewer.goTo(3);
const matches = await viewer.search("budget");
viewer.destroy();
```

```ts check
import { preview } from "aared/xlsx";

const viewer = await preview({ source: file, target: container });
await viewer.goTo(1); // Switch sheets
await viewer.xlsx.goToCell("D14");
viewer.destroy();
```

```ts check
import { preview } from "aared/docx";

const viewer = await preview({
  source: file,
  target: container,
  pagination: { mode: "layout" },
});
await viewer.docx.goToPage(2);
viewer.destroy();
```

```ts
// Exported from each format entry, alongside its matching preview handle:
interface PptxPreviewInput extends Omit<PreviewInput, "type" | "pagination"> {}
interface XlsxPreviewInput extends Omit<PreviewInput, "type" | "pagination"> {}
interface DocxPreviewInput extends Omit<PreviewInput, "type"> {}
```

The handles are the same `PptxPreview`, `XlsxPreview` and `DocxPreview` described
below, with the same navigation, zoom, appearance, search, events and teardown.
Each format also re-exports `PreviewSearchOptions`, `PreviewEventMap`,
`SearchNavigation` and `SearchNavigationState`. XLSX preview shows sheet tabs by
default; its low-level `render()` leaves them off. DOCX preview defaults to flow
mode; page navigation needs layout mode. No `type` option is needed or accepted
by the single-format inputs.

For shared documents, resolved models or several rendered units, use the
existing `open()` + `render()` instead: render `destroy()` and document
`close()` remain separate. The format-local viewer does not expose its owned
document. Its Worker still contains all three parsers; only renderer code is
isolated. The auto-detect entry below still emits all format chunks and fetches
only the chosen one.

## Auto-detect preview (`aared/preview`)

```ts check
import { preview, detect, type PreviewHandle, type PreviewInput, type PreviewOptions } from "aared/preview";

const viewer: PreviewHandle = await preview({ source: file, target: container });
await viewer.goTo(2);
viewer.setZoom(1.5);
viewer.setAppearance({ theme: "dark" });  // in place: index, zoom, and session survive
if (viewer.format === "xlsx") await viewer.xlsx.goToCell("D14");  // narrowed: xlsx is non-null
viewer.destroy();
```

One call for embeds that take any file: the format is detected in the
Worker, only that format's code loads, and the returned `PreviewHandle` owns
navigation, zoom, events and teardown.

```ts
interface PreviewOptions {
  type?: DocumentFormat;   // assert a format, skip detection; mismatch rejects `unsupported-format`
  index?: number;          // starting unit index, default 0; goTo() changes it
  signal?: AbortSignal;
  fontResolver?: FontResolver;   // opt-in, forwarded to open() (see aared-fonts)
  worker?: WorkerInit;
  appearance?: Appearance;       // starting appearance; setAppearance() changes it
  zoom?: ZoomValue;              // starting zoom, default per format (see Zoom); setZoom() changes it
  mediaResolver?: MediaResolver; // override; defaults to the owning session
  pagination?: DocxPagination;   // DOCX flow or physical pages; ignored for other formats
}

interface PreviewInput extends PreviewOptions {
  source: Source;
  target: HTMLElement;
}

function preview(input: PreviewInput): Promise<PreviewHandle>;

// One handle type per format; checking `format` narrows to it.
type PreviewHandle = PptxPreview | XlsxPreview | DocxPreview;

interface PptxPreview extends PreviewBase {
  readonly format: "pptx"; readonly info: PptxInfo; readonly xlsx: null; readonly docx: null;
  search(query: string, options?: PreviewSearchOptions): Promise<PptxSearchMatch[]>;
}
interface XlsxPreview extends PreviewBase {
  readonly format: "xlsx"; readonly info: XlsxInfo; readonly xlsx: XlsxPreviewControls; readonly docx: null;
  search(query: string, options?: PreviewSearchOptions): Promise<XlsxSearchMatch[]>;
}
interface DocxPreview extends PreviewBase {
  readonly format: "docx"; readonly info: DocxInfo; readonly xlsx: null; readonly docx: DocxPreviewControls;
  search(query: string, options?: PreviewSearchOptions): Promise<DocxSearchMatch[]>;
}

// What every format's handle has (not exported: use PreviewHandle).
// addEventListener is typed by PreviewEventMap: indexchange, slidechange,
// sheetchange, zoomchange, error, and the forwarded linkactivate,
// cellactivate, selectionchange, plus searchchange for find position updates.
interface PreviewBase extends EventTarget {
  readonly searchNavigation: SearchNavigation;
  readonly index: number;
  readonly zoom: ZoomValue;          // the requested zoom, kept across goTo()
  readonly defaultZoom: ZoomValue;   // the zoom this format opens at (see Zoom)
  readonly scale: number;            // the scale actually painted
  goTo(index: number): Promise<void>;  // emits `indexchange` + `slidechange`/`sheetchange`
  next(): Promise<void>;               // one unit on; nothing at the last
  previous(): Promise<void>;           // one unit back; nothing at the first
  setZoom(zoom: ZoomValue): void;      // emits `zoomchange` when the value changes
  zoomIn(step?: number): void;         // zoom + step (default 0.1 = 10 points), at most 300%
  zoomOut(step?: number): void;        // zoom - step (default 0.1), at least 25%
  resetZoom(): void;                   // back to defaultZoom
  setAppearance(appearance: Appearance): void;  // replaces, in place: index and zoom survive
  destroy(): void;                     // full teardown: render + worker + painted DOM
}

interface XlsxPreviewControls {
  readonly selection: CellRef | null;
  goToCell(cell: string): Promise<void>;
  scrollTo(target: { cell?: string; range?: string; align?: "start" | "center" | "end" }): void;
  focus(cell: string): void;
}

interface PreviewSearchOptions extends ReadOptions {
  highlight?: boolean;  // default true; false clears previous highlights
}

interface SearchNavigationState {
  readonly index: number | null; // active position, zero-based; null when inactive
  readonly count: number;
}
interface SearchNavigation extends SearchNavigationState {
  next(): Promise<void>;     // select, reveal and outline the next match; wraps
  previous(): Promise<void>; // same, in reverse
}

interface DocxPreviewControls {
  readonly pageCount: number;                 // 0 in flow mode
  readonly pages: readonly DocxPageInfo[];    // [] in flow mode
  readonly headings: readonly HeadingInfo[];  // body outline, in document order
  goToHeading(target: string | number): Promise<void>;
  goToPage(index: number): Promise<void>;
  goToSearchMatch(match: DocxSearchMatch): Promise<void>;     // flow and layout
}
```

`index`/`goTo()` switch **units** — slides, sheets, or the one DOCX document.
Moving **within** the unit on screen is format-specific, so it hangs off
`viewer.xlsx` (cells) and `viewer.docx` (headings and pages), with the same
methods the format's own render handle has (see [Navigation](#navigation)).
They are `null` for the other formats, so `viewer.format === "xlsx"` makes
`viewer.xlsx` non-null. Each is one object for the viewer's whole life,
acting on whichever unit is on screen: one kept across `goTo()` keeps
working, and after `destroy()` its moves reject with `closed`. PPTX has no
places inside a slide, so there is no `viewer.pptx`. The `DocxPageInfo`,
`DocxPagination`, `HeadingInfo` and `SoftBreakPolicy` types, and the three
search match types, are re-exported from `aared/preview` for convenience.

`search(query)` runs the format's search ([Search grammar](#search-grammar))
over the document the viewer already has open, so a search box needs no
second `open()`. It returns results and highlights painted matches by default
in every format. Each new search replaces the active query; an empty query
clears it. The application owns the search input, visibility toggle and results
list; these controls are not built into the package. Each match is a place to go:

For a compact find bar, use `viewer.searchNavigation.index` and `.count` to
display “2 of 4”, and call `.next()` / `.previous()` for the arrows. Listen to
`searchchange` for counter updates. All occurrences get a soft highlight;
the current match gets a stronger fill and outline, without changing text layout.
Steps wrap at both ends. PPTX navigates occurrences across slides; XLSX navigates
matching cells on the active sheet, including virtualized rows; DOCX navigates
painted occurrences, including each displayed header/footer copy. Its navigation
count can therefore exceed the deduplicated source results returned by `search()`.
Empty or data-only search resets navigation to `{ index: null, count: 0 }`.

```ts check
import { preview } from "aared/preview";

const viewer = await preview({ source: file, target: container });
await viewer.search("nile");
await viewer.searchNavigation.next();
const { index, count } = viewer.searchNavigation;
console.log(index === null ? "No active match" : `${index + 1} of ${count}`);
await viewer.searchNavigation.previous();
```

| Format | A match | Go there |
|---|---|---|
| PPTX | `slide` (`UnitRef`), `text` | `viewer.goTo(match.slide.index)` |
| XLSX | `address`, `text` (on the sheet on screen; `sheet` names it) | `viewer.xlsx.goToCell(match.address)` |
| DOCX | `kind`, `heading` (nearest above, or `null`), `text`, optional `story` | `viewer.docx.goToSearchMatch(match)` |

```ts check
import { preview } from "aared/preview";

const viewer = await preview({ source: file, target: container });
// Results and highlights together:
const matches = await viewer.search("revenue");
// Results only; also clears previous highlights:
await viewer.search("revenue", { highlight: false });
// Clear the active search:
await viewer.search("");

if (viewer.format === "pptx") {
  const [first] = await viewer.search("revenue");
  if (first !== undefined) await viewer.goTo(first.slide.index);
}
```

Behavior notes:

- A URL is fetched once for detection and opening together.
  `detect(source, { signal })` runs the probe alone, opening nothing.
- A document with nothing to show (no slides, sheets or sections) rejects
  with `invalid-document`; there is never a handle over an empty document.
- A workbook shows its sheet tabs unless `appearance.spreadsheet.sheetTabs`
  is `false`. `setAppearance()` replaces the appearance whole, and what it
  leaves out goes back to that default, so `setAppearance({ theme: "dark" })`
  keeps the tabs; a host that hides them passes `sheetTabs: false` each time.
- The newest `goTo()` wins: an overtaken one resolves having changed nothing.
  A failed one rejects and also fires `error` (`{ message, cause }`, the
  element's shape), so a dropped promise is still heard; the unit on screen
  stays. After `destroy()` it rejects with `closed`.
- A toolbar is the viewer's own methods behind buttons (`viewer.next()`,
  `viewer.previous()`, `viewer.zoomIn()`, `viewer.zoomOut()`,
  `viewer.resetZoom()`, reading `viewer.defaultZoom`), as the element's
  built-in bar is. `next()` and `previous()` step on from where the newest
  move is heading, so three quick presses move three units, and do nothing
  at either end (a DOCX is one unit). `zoomIn(step)` and `zoomOut(step)` add
  or take away `step`, where `1` is 100% (default `0.1`, so 100% to 110%;
  a step that is not above 0 throws `invalid-argument`). From a fit mode they
  start at the scale on screen, so a slide fitted at 62% goes to 72%. They
  round to whole percents and stay within 25%–300%. `resetZoom()` goes back
  to `defaultZoom`, the zoom the format opens at; for a slide or a document
  that is a fit mode, not `setZoom(1)`, which pins the natural size.
- A failed `search()` only rejects: it fires no `error`, which reports moves
  (the hooks show it as `navigationError`). `signal` cancels it; after
  `destroy()` it rejects with `closed`. The first search of a deck or
  workbook reads every slide or sheet through the Worker the viewer paints
  from; later ones reuse the text it kept.
- `destroy()` is the whole teardown (render, Worker session, painted DOM);
  there is no separate `close()`. The target element stays yours.
- The events are the element's (it runs on this same viewer):
  `indexchange` with `slidechange` or `sheetchange` beside it (a sheet-tab
  click included), plus the render handle's, forwarded.

## React hooks (`aared/react`)

```tsx check
import { messageFor } from "aared/core";
import { usePptx } from "aared/react";

function SlidePreview({ file }: { file: File }) {
  const { ref, status, viewer, index, error, navigationError, retry } = usePptx({ source: file });
  return (
    <>
      <div ref={ref} />
      {status === "loading" && <p>Loading…</p>}
      {status === "error" && <p>{messageFor(error)} <button onClick={retry}>Retry</button></p>}
      {status === "ready" && (
        <p>
          {viewer.info.titles[index]}{" "}
          {/* A failed move lands in navigationError; the rejection needs no handling of its own. */}
          <button disabled={index >= viewer.info.count - 1} onClick={() => void viewer.next().catch(() => {})}>Next</button>
        </p>
      )}
      {navigationError !== null && <p>That slide could not be shown.</p>}
    </>
  );
}
```

`usePreview()` mounts `preview({ source, target })` inside an effect and owns
what every embed otherwise rewrites: the `AbortController`, the
loading/ready/error state, `index`/`zoom` mirroring from handle events, and
full teardown on unmount or source change. `usePptx()`, `useXlsx()`, and
`useDocx()` are the same hook with `type` asserted — detection is skipped,
only that format's chunk is fetched at runtime (bundlers still emit all
three), and `viewer` is a `PptxPreview` / `XlsxPreview` / `DocxPreview`. The
wrappers add no lifecycle of their own.

The result is one shape per `status`. Checking it tells TypeScript what is
there, destructured or not: once `"ready"`, `viewer`, `index` and `zoom` are
set (in the example, `viewer.info` needs no null check); once `"error"`,
`error` is an `AaredError`; before either, all of them are `null`. The
document's `info` and `format` are read from `viewer`.

`index` and `zoom` are start values; the viewer's methods change them, and the
result follows the screen. Buttons call the viewer directly (as `viewer.goTo()`
above). `appearance` is reactive: a dark-mode switch updates the same viewer
without another effect or reopening the document:

```tsx check
import { usePreview } from "aared/react";

function ThemedPreview({ file, theme }: { file: File; theme: "light" | "dark" }) {
  const { ref } = usePreview({ source: file, appearance: { theme } });
  return <div ref={ref} />;
}
```

```ts
interface UsePreviewOptions extends Omit<PreviewOptions, "signal"> {
  source: Source;   // must be referentially stable: pass the bytes you hold, not a copy per render
  // type, index, zoom, appearance, fontResolver, mediaResolver, worker,
  // pagination — as on preview(); index and zoom are start values, appearance is reactive
}

type UsePreviewPhase = "idle" | "loading" | "ready" | "error";

type UsePreviewResult<V extends PreviewHandle = PreviewHandle> =
  UsePreviewPending | UsePreviewReady<V> | UsePreviewFailed;

// Every state also has: ref (attach: <div ref={ref} />) and retry (re-run
// the mount, from the latest start values). Changes go through viewer.
interface UsePreviewPending { status: "idle" | "loading"; viewer: null; index: null; zoom: null; error: null; navigationError: null }
interface UsePreviewReady<V extends PreviewHandle = PreviewHandle> {
  status: "ready";
  viewer: UsePreviewViewer<V>;            // viewer.info, viewer.format, viewer.xlsx / viewer.docx
  index: number;                          // mirrored from `indexchange`
  zoom: ZoomValue;                        // mirrored from `zoomchange`; the painted scale is viewer.scale
  error: null;
  navigationError: AaredError | null;     // the last failed navigation (the handle's `error`); the page stays
}
interface UsePreviewFailed { status: "error"; viewer: null; index: null; zoom: null; error: AaredError; navigationError: null }

// The preview() handle without destroy(): teardown is the hook's (unmount,
// a new source, retry()). Per format, so checking `format` still narrows it.
type UsePreviewViewer<V extends PreviewHandle = PreviewHandle> = V extends PreviewHandle ? Omit<V, "destroy"> : never;

// usePptx → UsePreviewResult<PptxPreview>, useXlsx → <XlsxPreview>, useDocx → <DocxPreview>
interface UsePptxOptions extends Omit<UsePreviewOptions, "type" | "pagination"> {}
interface UseXlsxOptions extends Omit<UsePreviewOptions, "type" | "pagination"> {}
interface UseDocxOptions extends Omit<UsePreviewOptions, "type"> {}
```

Behavior notes:

- The hook owns the host element's contents while mounted and clears them
  on teardown, so its `viewer` has no `destroy()`. Swapping `source`
  mid-flight cancels the stale mount, which never reaches `"error"` and
  never paints over the new one.
- Failures land in state. A failed mount sets `status: "error"`. A failed
  navigation (`viewer.goTo()`, or a move on `viewer.xlsx`/`viewer.docx`)
  sets `navigationError` while `status` stays `"ready"` and the unit on
  screen stays; the next unit change clears it.
- `index` and `zoom` are start values, read when the document mounts. Later
  changes take effect on the next mount (`source` change or `retry()`);
  `viewer.goTo()` and `viewer.setZoom()` change what is on screen now.
- `appearance` updates in place when its field values change, preserving the
  viewer, Worker session, unit, zoom and selection. Removing it resets the
  defaults. Inline objects and property order do not trigger extra updates.
  An imperative `viewer.setAppearance()` remains effective until the option's
  values change or the viewer remounts.
- `type` and `pagination` re-open the document when their value changes;
  inline literals don't, since they are compared by value. `source` is
  compared by identity: hold the same `File`/`Blob`/URL or bytes across
  renders (a `Uint8Array` kept in state is stable; a copy made per render
  is not).
- The function options never re-open it on their own, so inline functions
  are fine: a `mediaResolver` is called through the latest one given (adding
  or removing one re-opens), and `fontResolver` and `worker` are read at the
  next mount (a `source` change or `retry()`).
- The result object keeps its identity until something in it changes, so it
  can be an effect dependency.
- StrictMode-safe: mount, cleanup and remount resolve once, leaking nothing.
- Search is `viewer.search()`, as on `preview()`; range reads and media stay
  on the low-level API. A DOCX document is one unit, so its
  `viewer.goTo()` takes only `0`.
- `react` (`>=18`) is an optional peer.

## Design principle

Separate format entrypoints, shared API grammar, native terminology:

> **Same API grammar, format-native vocabulary.**

```ts check
import * as pptx from "aared/pptx";
import * as xlsx from "aared/xlsx";
import * as docx from "aared/docx";

const deck = await pptx.open(file);
const slideView = await pptx.render({ slide: deck.slides.get(0), target: container });

const workbook = await xlsx.open(file);
const sheet = workbook.sheets.get("Revenue");
const data = await sheet.read({ range: "A1:M200" });
const sheetView = await xlsx.render({ sheet, target: container });

const doc = await docx.open(file);  // not `document`: that would shadow the page's
const docView = await docx.render({ document: doc, target: container });
```

The nouns differ because the formats differ; the lifecycle (`open()`, the
collection's `list()`/`get()`, `read()` where it applies, `render()`,
`destroy()`, `close()`) and these rules are the same in every format and
layer:

1. **Units and places.** `count` and `goTo(i)` switch units: a slide, a
   sheet, or the one DOCX document. Moving inside the unit on screen is
   `goTo<Place>()` (see [Navigation](#navigation)).
2. **Every `goTo…` returns `Promise<void>`.** A target that doesn't exist
   rejects `not-found`; an index that is not a whole number, `invalid-argument`.
3. **A unit is `{ index, title }`** (`UnitRef`) and **a cell
   `{ address, row, col }`** (`CellRef`, zero-based), everywhere.
4. **A title lookup** matches exactly, then ignoring case; never a substring
   (that is `search()`).
5. **Events describe changes.** The ready signal (`load`, `preview()`
   resolving, the hook's `"ready"`) carries the starting state.
6. **Start values and updates are explicit.** `index` and `zoom` say where a
   viewer starts; changing these hook options later waits for the next mount.
   React `appearance` changes apply in place; removing it resets defaults.
   `goTo()`, `setZoom()` and `setAppearance()` (which replaces it whole)
   change the mounted viewer, events report
   the change, and the state a layer shows (`viewer.index`, the hook's
   `index`, the element's attributes) is a copy of the screen. Structural
   options such as `pagination` re-open the document and have the same name
   in `render()`, `preview()` and the hooks.
7. **One error model:** every failure is an `AaredError`, with the same
   `code` for the same situation in every layer ([Errors](#errors)).
8. **After `destroy()`** viewer navigation and search reject with `closed`;
   zoom and appearance setters do nothing, and repeated cleanup is harmless.
   Low-level render handles expose `destroyed` and stop changing their output.
   A render that a newer `render()` into the same target replaced destroys itself.

### Navigation

| | PPTX | XLSX | DOCX |
|---|---|---|---|
| Unit (`count`, `goTo(i)`) | a slide | a sheet | the document (`count` 1) |
| Places in a unit | — | cells: `goToCell`, `scrollTo`, `focus`, `selection` | headings: `goToHeading` (both modes); pages: `goToPage`, `pages`, `pageCount` (layout mode) |
| Switching units on the render handle | render another slide | `goToSheet(key)`, the sheet tabs | — |

Word works the same way: headings are document structure and work in every
view (the Navigation pane); pages are layout and exist only in Print Layout.
So DOCX `goToHeading` works in flow and layout mode, while `goToPage` rejects
with `unsupported-feature` in flow mode, where `pageCount` is `0` and `pages`
is empty.

### Zoom

Every render handle and viewer has the same zoom: `setZoom(zoom)`, the
requested `zoom`, and the `scale` it actually painted. `zoom` can also be
passed to `render()` and `preview()` (and set as the element's attribute) to
start there without an event.

| `ZoomValue` | Meaning |
|---|---|
| `"fit-width"` | Scale so the content's width fills the container |
| `"fit-page"` | Scale so the whole content fits the container's width *and* height. A container that only grows with its content offers no height, so this falls back to `fit-width` |
| a number | An explicit scale — `1` is 100% (96 CSS px per inch) |

| Format | Default | What is scaled |
|---|---|---|
| PPTX | `"fit-page"` | the slide |
| XLSX | `1` — 100%, like Excel | the grid, headers included. Fit modes fit the sheet's used area (never the fill cells), with a 25% floor so a huge sheet stays readable and virtualized |
| DOCX | `"fit-width"` | layout mode: the pages — `fit-width` fits the widest, `fit-page` also keeps the tallest in view. Flow mode: fit modes are 100%, since the column already flows to its container; a number scales it |

Fit modes re-fit when the container resizes. Zoom belongs to the viewer: it
survives `goTo()` in `preview()`, the hooks and the element. Their viewer
also reads the default back (`defaultZoom`) and steps it the way a toolbar
does (`zoomIn()`, `zoomOut()`, `resetZoom()`; see the
[auto-detect preview](#auto-detect-preview-aaredpreview)). How much room the host must
give is on the Start page: [Sizing](/start/#sizing).

### Slides

Collection entries are lightweight handles — `open()` indexes, `read()`
parses:

```ts
interface SlideInfo extends UnitRef {   // { index, title }
  size: { width: number; height: number };  // inches
}

class SlideHandle {
  readonly info: SlideInfo;
  read(options?: ReadOptions): Promise<SlideModel>;
  media(mediaId: string, options?: MediaOptions): Promise<ArrayBuffer>;
}

for (const slide of deck.slides.list()) {
  console.log(slide.info.index, slide.info.title);
}
const slide = deck.slides.get(0);
const model: SlideModel = await slide.read();
```

A slide's `title` is `"Slide N"` (1-based): its real title text needs the
slide parsed, which `open()` never does, so read it from `slide.read()`.

### Rendering a slide

```ts
interface PptxRenderInput {
  slide: SlideHandle | SlideModel;
  target: HTMLElement;
  appearance?: Appearance;
  zoom?: ZoomValue;               // default "fit-page"
  mediaResolver?: MediaResolver;
  signal?: AbortSignal;           // cancels before the paint (see Cancellation)
}

// addEventListener is typed by PptxRenderEventMap: zoomchange, linkactivate.
interface PptxRenderHandle extends EventTarget {
  readonly slide: SlideInfo;
  readonly zoom: ZoomValue;
  readonly scale: number;
  readonly destroyed: boolean;
  readonly warnings: readonly RenderWarning[];  // elements with no id, and font fidelity, for PPTX
  setZoom(zoom: ZoomValue): void;
  setAppearance(appearance: Appearance): void;
  destroy(): void;
}

interface RenderWarning {
  code: string;     // e.g. "font-unavailable", "pptx-missing-id"; stable, safe to switch on
  message: string;  // for a human
}

const slideView = await render({ slide, target: container });
slideView.setZoom(1.5);           // emits `zoomchange`
slideView.setAppearance({ theme: "dark" });  // theme marker only; slides stay source-faithful
slideView.destroy();
```

`slideView.warnings` is empty unless the render noticed something off. Today that
is a font it could not paint with (`font-unavailable`: neither the requested
family nor a substitute, so the browser's own fallback painted), and a slide
whose file gave some shapes, pictures, charts, tables or groups no id
(`pptx-missing-id`, once per slide; the file is damaged, but PowerPoint's own
repair only adds the ids, so aared does the same and draws the slide in full).
The model carries the count as `SlideModel.missingIds`. DOCX and XLSX give the
same kind of warning (`docx-missing-id`, `xlsx-missing-id`: Word and Excel also
call a drawing with no id damaged and offer to repair it, and aared draws it in
full); their models carry the count as `DocumentSection.missingIds` (on the
first section, for the whole document) and `SheetModel.missingIds`. The slide shows as soon
as it is painted; `render()` resolves once its fonts arrive (at most two
seconds), since it reads which font painted.

`render()` takes a handle (read on demand, media from its session) or an
already-read model. `paintSlide(input)` is the synchronous paint underneath,
for a model you hold; it reads `warnings` against whatever fonts have
arrived at that moment:

```ts
interface PaintSlideInput {
  model: SlideModel;
  target: HTMLElement;
  appearance?: Appearance;
  zoom?: ZoomValue;
  mediaResolver?: MediaResolver;
}

const slideView = paintSlide({ model, target: container, mediaResolver: (id) => deck.media.get(id) });
```

### Backgrounds and master graphics

A slide paints its background, then its layout's and master's graphics (a
logo, a header box; placeholders never paint), then its own elements.
`SlideModel.background` is already resolved through layout and master, a
`ShapeFillModel` painted like any fill; one that cannot paint stays white
and marks the slide `data-aared-background="unsupported"`.
`SlideModel.layout` (`SlideLayoutModel`) is one object shared by every slide
on that layout: read-only, like every model. What each fill and text feature
paints is in ARCHITECTURE's format rules.

### Searching a deck

```ts
interface PptxSearchMatch {
  slide: UnitRef;  // { index, title } — goTo(slide.index)
  text: string;    // this occurrence's paragraph text (at most 120 characters)
}

const matches = await deck.search("revenue", { signal });
```

One result per non-overlapping text occurrence, in slide/paragraph order.
Several results can name the same slide, including repeated occurrences in
one paragraph. Each result navigates to its slide; highlighting marks every
painted occurrence. Cancellation is checked between slides. See
[Search grammar](#search-grammar).

Hyperlinks, on a run or a whole shape, paint as real anchors that notify
instead of navigating: `linkactivate` with `{ target }`, the URL, or for a
jump inside the deck a `#`-prefixed part path for the host to decide.

### Sheets and range reading

```ts
interface SheetInfo extends UnitRef {   // { index, title } — title is the tab name
  state: "visible" | "hidden" | "veryHidden";
}

interface SheetReadOptions extends ReadOptions {
  range?: string | CellRange;   // omitted: the whole sheet
}

class SheetHandle {
  readonly info: SheetInfo;
  read(options?: SheetReadOptions): Promise<SheetRangeModel>;
  search(query: string, options?: ReadOptions): Promise<XlsxSearchMatch[]>;   // this sheet only
  media(mediaId: string, options?: MediaOptions): Promise<ArrayBuffer>;
}
```

A range is an A1 string (`"A1:M200"`, or one cell `"D14"`) or a structured
`CellRange`. Reversed A1 corners are put in order; a reversed `CellRange`, or
a malformed reference, rejects with `invalid-range`.

```ts
const data = await sheet.read({ range: "A1:M200" });
const cell = await sheet.read({ range: "D14" });
const block = await sheet.read({ range: { start: { row: 0, col: 0 }, end: { row: 199, col: 12 } } });
```

`read()` returns a `SheetRangeModel`: the whole sheet's metadata (name,
extent, frozen panes, column widths, merges, drawings) with `rows` cut to the
range and merges clipped to it; rows outside it read as empty. The Worker
keeps the parsed sheet, so another range is a slice, not a re-parse.

**Sizing a sheet yourself.** `zoom: "fit-width"` or `"fit-page"` fits the
sheet's used area for you (see [Sizing](/start/#sizing) for the host). To lay it
out yourself, the model has the used range as `extent` (`{ cols, rows }`),
`columnWidths` and `defaultRowHeight` in inches, and a row's own height as
`rows[n].height`; the numbers leave out the viewer's headings and tabs.

```ts
interface SheetRangeModel extends SheetModel {
  range: CellRange;   // the window that was read, zero-based inclusive
}
```

### Rendering a sheet

```ts
interface XlsxRenderInput {
  sheet: SheetHandle | SheetModel | SheetRangeModel;
  target: HTMLElement;
  appearance?: Appearance;
  zoom?: ZoomValue;               // default 1 (100%, like Excel)
  mediaResolver?: MediaResolver;
  signal?: AbortSignal;           // cancels before the paint (see Cancellation)
}

// addEventListener is typed by XlsxRenderEventMap (the events table below).
interface XlsxRenderHandle extends EventTarget {
  readonly sheet: SheetInfo;
  readonly selection: CellRef | null;
  readonly zoom: ZoomValue;
  readonly scale: number;
  readonly destroyed: boolean;
  readonly warnings: readonly RenderWarning[];  // drawings with no id (`xlsx-missing-id`), and font fidelity
  setZoom(zoom: ZoomValue): void;
  setAppearance(appearance: Appearance): void;
  goToCell(cell: string): Promise<void>;
  scrollTo(target: { cell?: string; range?: string; align?: "start" | "center" | "end" }): void;
  focus(cell: string): void;
  goToSheet(key: string | number): Promise<void>;
  destroy(): void;
}

const sheetView = await render({ sheet, target: container });
await sheetView.goToCell("D14");          // select + scroll + focus
sheetView.scrollTo({ range: "F120:J140", align: "center" });
sheetView.focus("F120");                  // select + focus, no scrolling
await sheetView.goToSheet("Revenue");     // switch tabs by title or index; stale reads cancel
sheetView.destroy();
```

`goToCell` and `focus` take one cell; `scrollTo` takes exactly one of `cell`
(one cell) or `range`. Anything else — a range where a cell belongs, an
empty target, a malformed address — is an `invalid-range` `AaredError`
(`goToCell` rejects with it; `focus` and `scrollTo` throw it). `goToSheet`
needs a `SheetHandle` input to reach the workbook; after rendering a bare
model it rejects `unsupported-feature`. Through a preview viewer these are
the `xlsx` place: `viewer.xlsx.goToCell`, `viewer.xlsx.scrollTo`,
`viewer.xlsx.focus`, `viewer.xlsx.goToSheet`.

`render()` takes a handle (read on demand) or an already-read model. Rows are
virtualized for you; columns paint in full.

The default render looks like a spreadsheet: headings and the read-only
selection are on, sheet tabs are off (the host owns tab switching). Turn
pieces off explicitly:

```ts
await render({
  sheet,
  target: container,
  appearance: { spreadsheet: { headers: false, selection: false, gridlines: "hide" } },
});
```

The selection is read-only but interactive: a click selects, the arrow keys,
Home, End and the page keys move, and Enter or a double-click activates
(`cellactivate`), with `role="grid"` semantics and one tab stop. Hyperlinks
notify instead of navigating. The events (`XlsxRenderEventMap`) name the
sheet as a unit and the cell as a cell location:

| Event | `detail` |
|---|---|
| `selectionchange` | `{ sheet: UnitRef; selection: CellRef \| null }` |
| `cellactivate` | `{ sheet: UnitRef; address; row; col; model: CellModel }` |
| `linkactivate` | `{ target: string; sheet: UnitRef; address; row; col }` |
| `sheetchange` | `UnitRef` — `{ index, title }` of the sheet now shown |
| `zoomchange` | `{ zoom: ZoomValue }` |

```ts
sheetView.addEventListener("cellactivate", (event) => console.log(event.detail.address));
sheetView.addEventListener("linkactivate", (event) => { /* host decides */ });
```

### Searching a workbook

```ts
interface XlsxSearchMatch extends CellRef {   // { address, row, col }
  sheet: UnitRef;   // { index, title }
  text: string;
  chart?: { name: string };   // a chart's word, at the chart's top-left cell
}

const matches = await sheet.search("revenue", { signal });
```

A workbook is searched one sheet at a time, as Excel's Find searches the
sheet you are on: `sheet.search()` covers that sheet alone, and the viewer's
`search()` covers the sheet on screen. For a workbook-wide search, loop over
`workbook.sheets.list()` (hidden sheets included).

One match per matching cell, against the cached, formatted value (formulas
are never evaluated). A chart's words (its title, axis titles, series names
and categories) match too, reported at the cell the chart is anchored to,
with `chart` set. See [Search grammar](#search-grammar).

A section is source structure, not a page: all of them arrive with `open()`,

```ts
const sections = doc.sections.list();
const section = doc.sections.get(0);
```

### Rendering a document

Flow is the default; physical pages are opt-in:

```ts
type SoftBreakPolicy = "ignore" | "prefer" | "force";

interface DocxPagination {
  mode?: "flow" | "layout";      // default "flow"
  softBreaks?: SoftBreakPolicy;  // default "prefer"
}

interface DocxRenderInput {
  document: DocxDocument | readonly DocumentSection[];
  target: HTMLElement;
  pagination?: DocxPagination;
  appearance?: Appearance;
  zoom?: ZoomValue;              // default "fit-width"
  mediaResolver?: MediaResolver;
  signal?: AbortSignal;          // cancels before the paint (see Cancellation)
}

interface DocxPageInfo {
  index: number;                 // zero-based; goToPage(index)
  width: number;                 // inches
  height: number;
  orientation: "portrait" | "landscape";
}

// addEventListener is typed by DocxRenderEventMap: zoomchange, linkactivate.
interface DocxRenderHandle extends EventTarget {
  readonly pageCount: number;              // 0 in flow mode
  readonly pages: readonly DocxPageInfo[]; // [] in flow mode
  readonly zoom: ZoomValue;
  readonly scale: number;
  readonly destroyed: boolean;
  readonly warnings: readonly RenderWarning[];  // layout-mode pagination edge cases, drawings with no id (`docx-missing-id`), and font fidelity in either mode
  setZoom(zoom: ZoomValue): void;
  setAppearance(appearance: Appearance): void;
  goToHeading(target: string | number): Promise<void>;
  goToPage(index: number): Promise<void>;
  goToSearchMatch(match: DocxSearchMatch): Promise<void>;
  destroy(): void;
}

const docView = await render({ document: doc, target: container });   // flow: pageCount 0
await docView.goToHeading("Introduction");   // by title, or goToHeading(2) by index
docView.destroy();

const pagedDocView = await render({
  document: doc,
  target: container,
  pagination: { mode: "layout", softBreaks: "prefer" },        // physical pages
});
await pagedDocView.goToPage(3);                    // layout mode only
```

Flow is one continuous article (with the last section's header and footer);
layout paints one box per page. `softBreaks` is what to do with the page
breaks Word stored at its last save (`w:lastRenderedPageBreak`): `"ignore"`,
`"prefer"` (default) or `"force"`. Every page stays in the DOM, so
find-in-page, selection and links reach all of it.

`goToHeading` works in both modes; `goToPage` rejects `unsupported-feature`
in flow mode and `not-found` outside the pages (see
[Navigation](#navigation)). Through a preview viewer this is the `docx`
place: `viewer.docx.goToHeading`. Passing the `DocxDocument` loads pictures through
its session; pass a `mediaResolver` only for a bare section list (without
one, its pictures paint as placeholders).

> **DOCX pages are laid out like Word's, but pixel-identical Word pagination
> is not part of the contract.**

### Searching a document

Sections are already in memory, so it resolves quickly; the blocks are
indexed on the first call:

```ts
interface DocxSearchMatch {
  kind: "heading" | "paragraph" | "list" | "table" | "footnote" | "endnote" | "chart" | "textBox" | "header" | "footer";
  section: number;
  heading: { index: number; title: string } | null;  // nearest preceding body heading
  text: string;
  table?: { index: number; row: number; col: number };  // kind "table"
  note?: { id: string; label: string };                 // notes
  textBox?: { index: number };                          // kind "textBox", document order
  story?: { part: string; variant: "default" | "first" | "even" }; // headers/footers
}

const matches = await doc.search("revenue", { signal });
```

Covers heading, paragraph, list, table-cell, text-box, and footnote/endnote text, one
match per matching block in document order, notes last, and a chart's words
(`kind: "chart"`, with the section and heading the chart sits under).

- **Tables.** `table.index` counts tables in the section in document order
  (nested tables included); `row` and `col` locate the innermost cell
  (`col` is the logical cell order, not the visual position in an RTL
  table). A heading inside a table cell does not change `heading`.
- **Headings.** `heading.index` is the outline index, so
  `docView.goToHeading(match.heading.index)` jumps to the match's heading.
- **Notes.** A note match reports the `section` and `heading` of the
  paragraph that first references it, where a reader meets the mark.
- **Headers and footers.** One result per matching block in a distinct source part,
  with `kind: "header"` or `"footer"`, `heading: null`, and `story` identifying
  its part and first indexed variant. Inherited copies do not repeat results;
  separate parts with identical text remain separate. Image alt text is not searched.

Text inside body text boxes is searched under `kind: "textBox"`; the
`textBox.index` identifies the box in section document order.

Viewer search highlights matching text by default in PPTX, XLSX and DOCX.
Pass `{ highlight: false }` to return results without highlighting and clear
previous highlights. An empty query clears the active search and returns `[]`.
Document and sheet APIs remain data-only.

The active query follows slide/sheet navigation and newly painted text, including
virtualized XLSX rows and repeated DOCX headers. Highlighting runs on the main
thread, using browser text ranges without changing layout. A browser without
CSS Custom Highlight support rejects a nonempty highlighted search with
`unsupported-feature`; data-only search remains available.
Highlighting code loads on the first highlighted search, on the main thread;
the Worker search protocol and resolved models are unchanged. Calling with
`{ highlight: false }` from the start skips the highlighting chunk.
`goToSearchMatch(match)` on DOCX controls scrolls to the first displayed
header/footer copy or nearest body heading. An undisplayed header/footer
rejects with `not-found`; flow mode shows only the final default pair.
Search includes saved field text; highlighted page fields use displayed values.

The app owns the search input and results list. The package handles highlighting
and navigation. For example, with the preview API:

```ts check
import { preview } from "aared/preview";

const viewer = await preview({
  source: file,
  target: container,
  pagination: { mode: "layout" },
});

if (viewer.format === "docx") {
  // Get results and highlight every occurrence, including repeated headers.
  const matches = await viewer.search("nile");

  // When the user clicks a result:
  if (matches[0]) {
    await viewer.docx.goToSearchMatch(matches[0]);
  }

  // When the user clears the search:
  await viewer.search("");
}

// When the viewer is no longer needed:
viewer.destroy();
```

### Sources and options

```ts

  signal?: AbortSignal;

```

**`fontResolver`** is optional, and leaving it out is the recommended setup:
nothing downloads, and a family the reader lacks paints in the browser's own
fonts (some lines then break a word differently from Office). A resolver is
called on the main thread for each family a read names; one that throws or
rejects never fails a read or a render: the family falls back, the render's
`warnings` names it (`font-unavailable`), and the next read asks again.

A resolver registers its `FontFace` under `fontAlias(requestedFamily)`,
never the requested name itself (that would shadow a reader who has the real
font) and never the substitute's own name (the renderer would not select
it). The repo's frozen, unpublished `aared-fonts` is such a resolver, for an
app that needs Office's line breaks exactly.

```ts check
import { fontAlias, type FontResolver } from "aared/core";

const resolver: FontResolver = async (requestedFamily) => {
  if (requestedFamily !== "Calibri") return undefined;
  const face = new FontFace(fontAlias(requestedFamily), "url(/fonts/carlito.woff2)");
  document.fonts.add(face);  // the browser fetches it when text first needs it
  return face;
};
```

### Worker override

By default `open()` starts the Worker from the self-contained `worker.mjs`
beside the package's other files: no configuration. That works with Vite,
webpack 5 and Next.js, in production builds, dev servers and under a
sub-path, and every entry can be imported where a server prerenders.

**Scripts on a CDN.** A browser never starts a Worker from a script on
another origin, so with your assets on another host `open()` rejects with
`worker-error`, naming the cause. Start the Worker from a same-origin Blob
that imports the worker file from the CDN (which must send
`Access-Control-Allow-Origin`, as for any module script):

```ts check
import { open } from "aared/pptx";

// The bundler emits the worker file with the other assets (on the CDN).
const workerUrl = new URL("aared/worker", import.meta.url);
const worker = () => new Worker(
  URL.createObjectURL(new Blob([`import ${JSON.stringify(workerUrl.href)};`], { type: "text/javascript" })),
  { type: "module" },
);
const deck = await open(file, { worker });
```

Set the `worker` option for a single-file bundle (`vite-plugin-singlefile`),
a strict CSP, or a bundler's own Worker constructor. A single-file bundle
inlines the same self-contained worker:

```ts
// Single-file bundles: a Blob URL from the inlined worker source
import workerSource from "aared/worker?raw";

const workerUrl = URL.createObjectURL(new Blob([workerSource], { type: "application/javascript" }));
const deck = await open(file, { worker: workerUrl });
```

Or a factory, here with Vite's `?worker` import of your own worker entry
(`./worker.ts` holds one line, `import "aared/worker";`):

```ts
import AaredWorker from "./worker?worker";

const deck = await open(file, { worker: () => new AaredWorker() });
```

`WorkerInit` is a script URL (`string` or `URL`) or a `() => Worker` factory;
`preview()`, `detect()` and `<aared-viewer>` (a property) take it too.

**Worker lifetime.** `close()` ends the session; pending reads reject with
`closed`. The Worker is kept for the next `open()` with the same `worker`
setting and stops about 15 seconds after the last document closes; two
documents open at once each get their own. A factory's Workers are yours:
one per document, terminated on `close()`.

### Styling and CSP

Renderer defaults (grid cells, paragraph and page boxes) are rules in one
constructed stylesheet on the root the render lives in, the document or a
shadow root; inline style carries only what the file authors, set through
the CSSOM. Nothing writes a `<style>` element or a style attribute,
`<aared-viewer>`'s chrome included, so a `style-src` without
`'unsafe-inline'` works (checked under `style-src 'self'` with every
format). The `aared-*` class names are internal; the styling hooks are the
`data-aared-*` attributes, `::part()` and the `--aared-*` tokens. Your CSS
beats a renderer default only with `!important` or a selector with two IDs
and a class. Render into an attached element; DOM serialised out of the page
(`outerHTML`) doesn't carry the defaults.

### Search grammar

A PPTX or DOCX document, and each XLSX sheet (`sheet.search()`), has an async
`search(query, options?)` for your own search box: each match is a location to
jump to (`goTo(match.slide.index)`, `goToCell(match.address)`,
`goToHeading(match.heading.index)`). These low-level searches return data only.
Viewer searches highlight matching painted text by default; pass
`{ highlight: false }` for results only, or search an empty string to clear.
A workbook is searched one sheet at a time, as Excel's Find is.
Switching sheets keeps the highlight query active; an application that displays
results should run `viewer.search(query)` again on `indexchange` to get the new
sheet's matches. The built-in viewers have no search
UI; `viewer.search()` on `preview()`, the hooks and the element runs the same
search on the viewer's own document, and on the sheet on screen for a workbook.

- A case-insensitive substring match over text, never formulas; an empty
  query returns `[]`, and each match's `text` is cut to 120 characters (the
  text as written, not as compared).
- Arabic spellings that readers treat as one word match each other: tashkeel
  and tatweel are ignored, every alef form (`أ إ آ ٱ`) matches `ا`, `ى`
  matches `ي`, and Arabic-Indic and Persian digits match Western ones, so
  `الانتاج` finds `الإنتاج` and `٢٤` finds `24`. Ta marbuta against ha, and
  the hamza on waw or ya, stay different letters. A query of only marks (a lone
  fatha) matches nothing. Title lookups (`sheets.get("Q1")`) stay case-only.
- The first PPTX search reads every slide from the Worker, so it grows with
  the file (timings in
  [BENCHMARKS.md](https://github.com/Abdo-Eid/aared/blob/main/docs/BENCHMARKS.md));
  `signal` cancels it between slides. The first search of an XLSX sheet reads
  that sheet only. Later searches scan the kept text in milliseconds. DOCX is
  already in memory.
- PPTX searches shape and table text; XLSX the sheet's formatted cells;
  DOCX headings, paragraphs, lists, table cells, notes, text boxes, headers
  and footers.
- After `close()` it rejects with `closed`.

### Appearance

The viewer's own look, passed to `render()`, `preview()` and the hooks
(structural styling is CSS: tokens and `::part()`):

```ts
type ViewerTheme = "light" | "dark" | "system";
type GridlineMode = "source" | "show" | "hide";

interface Appearance {
  theme?: ViewerTheme;
  spreadsheet?: {
    headers?: boolean;
    sheetTabs?: boolean;
    fill?: boolean;          // default true
    selection?: boolean;
    gridlines?: GridlineMode;
  };
}

type ZoomValue = "fit-width" | "fit-page" | number;
```

`theme` (default `"light"`) styles the viewer's chrome only, never the
document; see [Dark mode](#dark-mode).

`spreadsheet.sheetTabs` defaults by layer. The embed layers
(`<aared-viewer>`, `preview()`, the hooks) show a workbook's tabs unless it
is `false`, since they have no other way to switch sheets. The low-level
`render()` leaves them off unless it is `true`, for an app that draws its
own. `setAppearance()` replaces the appearance whole: what it leaves out goes
back to these defaults.

`spreadsheet.fill` (default `true`) continues the grid past the data with
empty cells and headings until the viewport is full, the way Excel's grid
never ends at your last row. The extra cells are inert: not part of the
extent, selection or navigation, and not addressable one by one. A sheet
that already fills the viewer gets none; `fill: false` paints only the
file's cells.

### Errors

One error model across all entrypoints:

```ts
class AaredError extends Error {
  code: AaredErrorCode;
  cause?: unknown;   // the underlying error, when there is one (see below)
}

type AaredErrorCode =
  | "unsupported-format"
  | "invalid-document"
  | "encrypted-document"
  | "unsupported-feature"
  | "network-error"
  | "media-error"
  | "not-found"
  | "invalid-range"
  | "invalid-argument"
  | "invalid-state"
  | "worker-error"
  | "internal"
  | "closed"
  | "aborted";

function isAaredError(error: unknown): error is AaredError;
function isAbort(error: unknown): error is Error;
function messageFor(error: unknown): string;
```

Every failure a public API reports is an `AaredError`. What each code means,
and where it comes from:

| Code | Meaning | Raised by |
|---|---|---|
| `invalid-document` | The file is not a readable document: not a ZIP, past the ZIP safety limits, not an Office package, malformed XML, a required part or element missing, an empty document | `open()`, `read()`, `search()`, `detect()`, `preview()`, the element |
| `encrypted-document` | Password-protected (an OLE container, not a ZIP) | `open()`, `detect()`, `preview()`, the element |
| `unsupported-format` | Not the format this entrypoint (or `type`) opens | `open()`, `preview()`, the element |
| `unsupported-feature` | A call this format, mode or input does not have: a range read outside XLSX, `goToPage()` in flow mode, `goToSheet()` on a sheet rendered from a bare model, no `Worker` in the environment | `read()`, `goToPage()`, `goToSheet()`, `open()` |
| `network-error` | A URL source failed to fetch, returned a non-2xx status, or stopped partway | `open()`, `detect()`, `preview()`, the element |
| `media-error` | `media.get()` for a part the document does not have | `media.get()` |
| `not-found` | A whole-number index, title, heading or layout that does not exist | `get()`, `goTo()`, `goToHeading()`, `goToPage()` |
| `invalid-range` | A malformed A1 range, cell or sheet window | `sheet.read({ range })`, `goToCell()`, `scrollTo()`, `focus()` |
| `invalid-argument` | A value that is not what the call takes: an index that is not a whole number, a source that is not a file, bytes or a URL | `get()`, `goTo()`, `goToPage()`, the element's `index`; `open()`, `detect()`, `preview()`, the element |
| `invalid-state` | A call the viewer is not ready for: the element's `open()` with no source | the element |
| `worker-error` | The Worker failed to start (including a browser refusing a Worker script from another origin), stopped, or a request could not be posted; every later call on that document reports it too | any call that reaches the Worker |
| `internal` | aared failed on this file: a defect in the viewer, not in the file. `cause` is the original error with its stack: include it in a bug report | any call that reaches the Worker |
| `closed` | Called after `close()` or `destroy()` | everything on a closed document or destroyed handle |
| `aborted` | Cancelled by your signal, or superseded by a newer call | anything that takes a `signal`; a replaced `open()` or `goTo()` |

```ts check
import { isAaredError } from "aared/core";
import { open } from "aared/xlsx";

try {
  const workbook = await open(file);
} catch (error) {
  if (isAaredError(error) && error.code === "encrypted-document") {
    // show a password-protected-file message
  }
}
```

**Messages** start with the entrypoint you called (`aared/pptx: …`), say what
failed, and say what to do when you can (a damaged file suggests re-saving
it in Office). They are English and for developers and logs; the wording may
change, `code` does not. `messageFor()` gives one short generic sentence per
code for a UI; a UI in another language maps `code` itself. **`cause`** is the
underlying error when there is one (for `internal`, the original error with
its stack: include it in a bug report).

**Embed layers.** `preview()`'s handle and `<aared-viewer>` reject *and* fire
`error` (`detail: { message, cause }`, the same instance) for a failure the
caller may not be awaiting, so handle one or the other, not both.
`usePreview()` turns them into state: `error`, `navigationError`.

**Aborts.** `isAbort()` matches every cancellation (`aborted`, and a
`DOMException` or `Error` named `"AbortError"`); cancellation keeps the name
`"AbortError"` so existing handling works, and every other `AaredError` is
named `"AaredError"`, so branch on `code`. A dead Worker (`worker-error`)
and a call after `close()` (`closed`) are deliberately not aborts: they are
failures to surface, not cancellations to ignore.

An unknown value in an otherwise readable file (an alignment PowerPoint
never writes) falls back to the default, as Office shows it.

### Cancellation

```ts check
import { isAbort } from "aared/core";
import { open } from "aared/xlsx";

const sheet = (await open(file)).sheets.get(0);
const controller = new AbortController();
const reading = sheet.read({ range: "A1:Z500", signal: controller.signal });
controller.abort(); // the Worker stops computing a model nobody will see
try {
  await reading;
} catch (error) {
  if (!isAbort(error)) throw error; // cancelled: nothing to show, nothing to report
}
```

`open(source, { signal })`, `read({ signal })`, `search(query, { signal })`
and `media.get(id, { signal })` reject with `aborted` when the signal aborts;
a URL's fetch is cancelled too. The Worker stops at its next safe point (a
decompression or XML parse already running finishes first). In-memory
bytes are copied once before they go to the Worker, so yours stay usable. A
newer navigation or render cancels the stale read it replaces.

`render({ signal })` cancels a render until it resolves. Before it paints
(reading the unit, or a document waiting for its fonts) it paints nothing;
after (a slide or sheet waiting for its fonts to report warnings) it takes
what it painted back out, and only that. Either way it rejects with
`aborted` and never hands back a handle, the way an aborted `fetch()` never
resolves. Once it has resolved the signal is ignored; `destroy()` is its
teardown. `preview()`, the hooks and the element do this for you. With low-level
PPTX `open()` + `render()`, paging is one render per slide into the same target,
each cancelling the one before, so the handle you keep is always the newest
call's:

```ts check
import { isAbort } from "aared/core";
import { open, render, type PptxRenderHandle } from "aared/pptx";

const deck = await open(file);
let latest: AbortController | undefined;
let shown: PptxRenderHandle | undefined;

async function show(index: number): Promise<void> {
  latest?.abort(); // a slower render still on its way never hands back a handle
  const mine = (latest = new AbortController());
  try {
    shown = await render({
      slide: deck.slides.get(index),
      target: container,
      signal: mine.signal,
      ...(shown === undefined ? {} : { zoom: shown.zoom }), // keep the reader's zoom
    });
  } catch (error) {
    if (!isAbort(error)) throw error; // a newer show() took over
  }
}
```

### `DocumentInfo`

Known right after `open()`, which reads only the document's manifest:
opening slide 1 never parses slides 2 to 200.

```ts
interface DocumentInfo {
  format: "pptx" | "xlsx" | "docx";
  count: number;          // units: slides / sheets / 1 for a document
  titles: string[];       // one label per unit
  sizes?: { width: number; height: number }[]; // inches, one per unit — PPTX only
  sheetStates?: Array<"visible" | "hidden" | "veryHidden">; // XLSX-only
  theme: { colors: Record<string, string>; fonts: { major: string; minor: string } };
}
```

`count` is the number of units `goTo()` takes (`0` to `count - 1`): slides,
sheets, or `1` for a document in either DOCX mode. "Unit" is the API's
neutral word; show people "slides", "sheets" or "document". Every per-unit
array is `count` long, so `titles[i]` and `sizes[i]` describe unit `i`:

| Format | `titles` | `sizes` |
|---|---|---|
| PPTX | `"Slide N"` (the real title text is in `slide.read()`) | One per slide, for reserving a thumbnail's aspect ratio before anything renders |
| XLSX | the sheet tab names | Omitted: a sheet has no page; read `extent` and column widths after `sheet.read()` |
| DOCX | the title from the file's properties, else `"Document"` | Omitted: page setup is per section (`doc.sections.list()`); laid-out pages are on the render handle's `pages` |

`theme` is the **file's own** Office theme (colour scheme, major and minor
fonts), not the viewer's `appearance.theme`.

## Resolved models

`read()` returns a format's own model, **fully resolved** in the Worker: text
runs carry browser-ready styles and table styles CSS colours, so nothing
needs a second lookup into theme or style XML. Models are read-only; shared
objects (a slide's `layout`, a sheet's shared cell styles) are the same
instance in every place that uses them.

> **Stability is undecided.** These model types are exported, but whether
> they are a stable public contract (versus experimental, or internal) is an
> open pre-release decision — see "Before first publish" in the
> [roadmap](https://github.com/Abdo-Eid/aared/blob/main/docs/ROADMAP.md). Until it is settled, expect their shape
> to change.

All PPTX slide coordinates are inches; `LocalViewBoxModel` is local unitless
SVG coordinates (a shape's geometry).

A chart (`ChartModel.spec` in a slide, `SheetChartModel.spec` in a sheet,
`DocxChartNode.spec` in a Word document) is a `ChartSpecModel`: what the chart plots and how it looks, every Office
default already applied. That covers its groups and series with their cached
values, the axes, legend and title, text looks in points (with the
complex-script face Arabic is set in), colours as CSS strings, and fills that
are not a plain colour as the same `ShapeFillModel` shapes use. Office 2016
charts (waterfall, histogram, treemap and the rest) read into the same model.
It is plain data (no markup, no `Map`), so it survives `JSON.stringify`. The
chart is laid out on the page, at its frame's size, when it is painted, as
Office lays it out, and named for screen readers by `ChartModel.alt` or
`SheetChartModel.alt` (the author's alt text), else its title. A chart the
preview does not draw has no `spec`; the frame shows a placeholder and
`unsupportedReason` says why: a surface or map chart, more than 100,000
points in a series (250,000 in all), or no cached values.

- PPTX: `SlideModel`, `SlideLayoutModel`, `SizeModel`, `BoundsModel`,
  `LocalViewBoxModel`, `SlideElementModel`, `ShapeModel`,
  `ShapeGeometryModel`, `ShapeFillModel`, `SolidFillModel`,
  `LinearGradientFillModel`, `LinearGradientStopModel`, `PathGradientFillModel`,
  `RelativeRectModel`, `PatternFillModel`,
  `PictureFillModel`, `PictureTileModel`, `UnsupportedShapeFillModel`, `StrokeModel`,
  `TransformModel`,
  `TableModel`, `TableRowModel`, `TableCellModel`, `PictureModel`,
  `ChartModel`, `ChartSpecModel`, `GroupModel`,
  `TextBodyModel`, `TextBodyVerticalAlign`, `TextDirection`, `TextAlign`,
  `TextAutofitMode`, `TextParagraphModel`, `TextRunModel`, `TextWrappingMode`,
  and `InsetsModel` (box insets in inches; also a Word cell's padding).
- XLSX: `SheetModel`, `SheetRangeModel`, `RowModel`, `CellModel`,
  `CellRange`, `XlsxCellType`, `XlsxCellStyleModel`, `SheetDrawingModel`,
  `SheetPictureModel`, `SheetChartModel` (charts share `ChartSpecModel` with
  PPTX), `SheetUnsupportedModel`.
  `CellModel` is the canonical readonly cell: cached `value`, `formatted`
  display string, `type`, optional `formula` source (never evaluated),
  `hyperlink`, authored `style`, and resolved `conditional` overlay.
  `SheetModel.unsupported` lists what the preview does not show, one entry
  per `kind`: a feature aared does not model (`pivot`, `macro`, `sparkline`,
  `data-validation`, `comment`, `conditional-format`, `drawing`, `other`), or
  `damaged`: the file itself is broken (cells, hyperlinks, merges or
  conditional-format ranges with an unreadable address, a drawing anchor or a
  picture or chart pointing at a missing part). Damaged items are counted per
  kind ("2 cells could not be read and were skipped; the file may be
  damaged"); everything readable around them still shows.
- DOCX: `DocumentSection`, `SectionProperties`, `HeaderFooterParts`,
  `SectionPageGeometry`, `SectionPageMargins`, `SectionBreakType`, `FlowNode`,
  `DocxParagraphNode`, `DocxHeadingNode`, `DocxTableNode`,
  `DocxTableRowNode`, `DocxTableCellNode`, `DocxImageNode`, `DocxChartNode`
  (a chart, placed exactly as a picture is), `DocxTextBoxNode`,
  `DocxDrawingNode` (the anchored picture, chart, or text box a paragraph's
  `floats` may hold), `DocxListNode`,
  `DocxListItemNode`, `DocxFootnoteNode`, `DocxUnsupportedNode`,
  `DocxPageBreakNode`, `DocxParagraphLayout`, `DocxParagraphBorder`,
  `DocxParagraphBorders`, `DocxTabStop`, `DocxInlineImage`, `DocxTableEdge`,
  `DocxTableBorders`. Paragraph alignment is `TextAlign` and cell padding is
  `InsetsModel`, both listed above with the PPTX text model.
  `SectionProperties.docGrid` carries the section's line-grid type and pitch;
  paragraph line spacing and `beforeLines`/`afterLines` follow that grid in the
  renderer. `DocxTextBoxNode` contains ordinary flow content plus its fixed
  extent, insets, optional fill/outline and vertical overflow behavior.
  A picture, chart or text box anchored in a paragraph (`wp:anchor`) is not a flow
  node: the paragraph or heading carries it in `floats`, each a
  `DocxDrawingNode` whose `anchor` (`DocxImageAnchor`, a `DocxAnchorPosition` per axis) holds what
  Word saved: the wrap, the side text may use, the position, the text
  distances in inches, and for tight and through wrapping the polygon.

What each PPTX field paints (fills, geometry, text styling, groups, line
spacing) is in ARCHITECTURE's format rules, not here.

## Dark mode

> **Theme changes `aared`, never the document.**

`theme` (default `"light"` on every layer; `"dark"` or `"system"` to follow
your site or the OS) styles the viewer's chrome: the element's stage and controls, the XLSX
tab bar and selection accent, and the `data-aared-theme` marker on each
render's root. Documents always paint as authored: a dark viewer shows light
sheets and pages on a dark stage, with no inversion or filters. Text with no
authored colour takes whichever ink reads better on its fill, as Office's
"Automatic" does.

One rule holds on every viewer layer (`<aared-viewer>`, `preview()` and the
hooks):

- **Unset is `light`**, whatever the OS says.
- **`light` and `dark` are fixed.** The OS never changes them.
- **`system` follows the OS**, now and on every flip, in place: the slide,
  sheet or page, the zoom and the Worker session stay. The viewer listens
  only while `system` is its theme; `viewer.setAppearance({ theme: "dark" })`
  (or the element's `theme` attribute) takes it over and the listener goes,
  and `destroy()` drops it too.

The low-level `render()` resolves `system` once, when it paints; an app that
owns the handle calls `handle.setAppearance()` again when the OS flips.

The element takes three CSS variables; a value you set wins in both themes:

```css
aared-viewer {
  --aared-background: #f2f2f2;   /* stage background (dark theme: #1c1c1f) */
  --aared-text: inherit;         /* stage text color */
  --aared-page-shadow: 0 1px 5px rgb(0 0 0 / 0.25);  /* page or slide drop shadow */
}
```

The renderers' own tokens (`--aared-surface`, `--aared-gridline`,
`--aared-selection`, `--aared-ink`) are internal, not inputs. For the
element's parts, see [Styling](#styling).

## Fidelity is part of the contract

`info` and rendered output only ever reflect what
the [fidelity contract](https://github.com/Abdo-Eid/aared/blob/main/docs/ARCHITECTURE.md)
promises per format. A non-recalculating XLSX formula is expected behavior,
not a bug — check that table before filing one. DOCX flow mode does not
paginate; layout mode aims for structural, not pixel-identical, pagination.

## Browser support

Baseline 2023 — Chrome/Edge 110+, Firefox 115+, Safari 16.4+. The floor is
set by the `deflate-raw` `DecompressionStream` (parsing runs in a module
Worker) and constructed stylesheets, both of which land at Safari 16.4 (Firefox
114 for module Workers). No polyfills are shipped for
browsers below this floor. Importing any entry, `aared/element` included,
touches no browser global (SSR-safe); the element registers itself only
where the page has a custom-element registry.
